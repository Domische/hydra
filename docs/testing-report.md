# Отчет о тестировании программных компонентов

## Область тестирования

Тестируемый компонент — стек хранения данных фронтенда:

- `LocalStorageAdapter`
- `BoardRepository`
- `ProjectService`
- `ProjectRepository`

Этот стек является критически важным узлом, поскольку он используется в рабочих процессах как проектов, так и досок, и служит границей между состоянием приложения и хранилищем браузера.

## Критические сценарии (узкие места)

1. **Поврежденное хранилище браузера**: некорректный JSON не должен приводить к сбою при запуске приложения или операции чтения.
2. **Отсутствующие данные**: отсутствующие ключи и неизвестные идентификаторы должны возвращать безвредный пустой результат или `null`.
3. **Различие между созданием и обновлением**: сохранение с тем же идентификатором должно обновлять запись, а не создавать дубликат.
4. **Поведение при удалении**: удаление одной записи должно сохранять несвязанные записи.
5. **Совместимость с устаревшими данными**: записи, созданные старыми версиями, должны получать безопасные значения по умолчанию.
6. **Интеграция сервисов и репозиториев**: операции создания, чтения, обновления и удаления должны согласованно сохраняться через границы абстракций.
7. **Сериализация в хранилище**: структурированные значения и примитивы должны корректно сохраняться и восстанавливаться.

## Автоматизированные тесты

Набор тестов включает:

- 5 модульных тестов для `LocalStorageAdapter`
- 6 модульных тестов для `BoardRepository`
- 1 интеграционный тест, связывающий `ProjectService` и `ProjectRepository`

Все 12 тестов успешно пройдены на текущей реализации.

Команды для запуска:

```bash
cd frontend
npm test
npm run test:coverage
```

Отчет о покрытии генерируется в `frontend/coverage/`. HTML-отчет находится в `frontend/coverage/index.html`.

## Анализ дефектов и рисков

### Обнаруженные дефекты

Сбоев тестов в критических сценариях сохранения данных, охваченных данным набором, не обнаружено.

### Потенциальные дефекты, требующие внимания

1. **Превышение квоты хранилища / ошибки записи**: `LocalStorageAdapter.set` не перехватывает `DOMException`, возникающую при превышении квоты или отключенном хранилище. В результате репозитории досок и проектов напрямую пробрасывают ошибки записи.
2. **Пустые заголовки**: `createBoard` и `createProject` не отклоняют пустые заголовки или заголовки, состоящие только из пробелов. Это следует валидировать, если заголовки обязательны согласно продуктовым правилам.
3. **Нарушение структуры коллекции**: некорректный JSON обрабатывается, но валидный JSON с неправильной структурой (например, объект вместо массива) может нарушить работу репозиториев.
4. **Параллелизм (конкурентность)**: операции чтения-изменения-записи в репозиториях синхронны в JS, но не защищены от пересечения с асинхронными вызовами.
5. **Доступность идентификаторов**: сервисы проектов и досок используют `crypto.randomUUID()`, который может отсутствовать в старых или небезопасных контекстах браузера.

## Рекомендуемые дальнейшие тесты

- Обработка ошибок при превышении квоты хранилища и его недоступности

- Кросс-репозиторные рабочие процессы: архивация проектов и связывание досок
- Поведение при дублировании и конкурентном сохранении
- Совместимость браузеров для генерации идентификаторов
