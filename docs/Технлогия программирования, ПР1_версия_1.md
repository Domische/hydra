# 1. Назначение и область действия

Документ определяет требования к первой версии веб-приложения для
визуального планирования. Пользователь создаёт доски, размещает на них
визуальные элементы и добавляет компонент-ссылку на другую доску.
Связанные доски образуют навигационную структуру, позволяющую переходить
между рабочими областями.

## 1.1. Цель продукта

Предоставить простой инструмент для создания визуальных досок,
размещения элементов и перехода между досками через компоненты-ссылки с
сохранением данных.

## 1.2. Входит в первую версию

- Создание, просмотр, переименование и удаление досок.
- Добавление и редактирование базовых визуальных элементов.
- Добавление компонента, ссылающегося на выбранную доску.
- Переход к целевой доске по компоненту.
- Сохранение досок, элементов и связей между перезагрузками страницы.
- Обработка ситуации, когда целевая доска удалена или недоступна.

## 1.3. Не входит в первую версию

- Совместное редактирование в реальном времени.
- Сложная система ролей и прав доступа, чат, комментарии и история
  версий.
- Мобильное приложение и офлайн-режим.

# 3. Термины

| Термин         | Определение                                                                                            |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| Доска              | Рабочая область, на которой пользователь размещает визуальные элементы.                                    |
| Визуальный элемент | Базовый объект на доске, например, текстовый блок или фигура; точный набор типов определяется реализацией. |
| Компонент-ссылка   | Элемент на исходной доске, который хранит ссылку на конкретную целевую доску и позволяет открыть её.       |
| Исходная доска     | Доска, на которой размещён компонент-ссылка.                                                               |
| Целевая доска      | Доска, на которую указывает компонент-ссылка.                                                              |

# 4. Пользовательские сценарии

| ID | Сценарий | Пользовательская потребность |
|-------|----------------|---------------------------------|
| US-01 | Создание доски | создать доску с названием, чтобы начать организовывать информацию |
| US-02 | Работа с элементами | добавлять и редактировать визуальные элементы, чтобы представить информацию |
| US-03 | Добавление компонента | разместить ссылку на другую доску, чтобы связать рабочие области |
| US-04 | Переход по компоненту | открыть целевую доску по компоненту |
| US-05 | Сохранение связи | компонент должен продолжать ссылаться на ту же доску после изменений и перезагрузки |
| US-06 | Повторное открытие | видеть сохранённые доски и элементы после повторного открытия приложения |

# 5. Функциональные требования

| ID | Название | Требование | Проверяемый результат |
|----|----|----|----|
| FR-01 | Создание доски | Система позволяет создать доску с непустым названием. | Доска отображается в списке и открывается. |
| FR-02 | Управление досками | Система позволяет просматривать список, переименовывать и удалять доски. | Новое название сохраняется после обновления; удалённая доска недоступна как существующая. |
| FR-03 | Визуальные элементы | Система позволяет добавлять базовые элементы и изменять их содержимое или поддерживаемые свойства. | Элемент и изменения сохраняются после обновления. |
| FR-04 | Компонент-ссылка | Система позволяет выбрать существующую целевую доску и добавить ссылку на неё на исходную доску. | Компонент виден на исходной доске и связан с выбранной целью. |
| FR-05 | Идентичность цели | Компонент хранит устойчивую ссылку на конкретную доску, а не только её название. | После переименования цель ссылки не меняется. |
| FR-06 | Переход к цели | Активация компонента открывает целевую доску. | Открывается именно выбранная при создании компонента доска. |
| FR-07 | Сохранение данных | Система сохраняет доски, элементы и связи между досками. | После обновления страницы данные доступны, связи работают. |
| FR-08 | Удалённая цель | Если цель удалена, исходная доска остаётся доступной, а компонент показывает состояние недоступности. | Нет аварии приложения; отображается понятное сообщение, переход не приводит к необработанной ошибке. |

# 6. Нефункциональные требования

| ID | Характеристика | Требование | Проверка |
|----|----|----|----|
| NFR-01 | Понятность | Основные действия доступны через интерфейс без обращения к исходному коду. | Пользователь выполняет US-01, US-03 и US-04 через интерфейс. |
| NFR-02 | Устойчивость | Недоступность целевой доски не должна приводить к аварийному завершению или потере исходной доски. | Тест удаления цели проходит без необработанной ошибки. |
| NFR-03 | Совместимость | Приложение работает в согласованном современном браузере. | В протоколе указаны браузер и версия, где выполнены проверки. |
| NFR-04 | Целостность | Переименование доски не меняет идентичность цели в компонентах. | После переименования компонент открывает прежнюю целевую доску. |

# 7. Ограничения и допущения

- Проект выполняется командой из четырёх человек в рамках учебного
  задания и ограниченного срока.
- Рабочий процесс организован по Kanban; задачи видимы команде.
- В первой версии поддерживается согласованный базовый набор визуальных
  элементов.
- Совместное редактирование в реальном времени и сложные права доступа
  не входят в обязательный объём.
- Компонент-ссылка указывает на одну целевую доску.

# 8. Критерии приёмки

| ID | Связь | Условие приёмки |
|----|----|----|
| AC-01 | FR-01 | Создать доску «План»: она появилась в списке и открывается. |
| AC-02 | FR-02 | Переименовать доску, обновить страницу и проверить новое название. Удалить тестовую доску и убедиться, что она больше не открывается как существующая. |
| AC-03 | FR-03 | Добавить элемент, изменить содержимое, обновить страницу. Элемент и изменения сохранены. |
| AC-04 | FR-04 | Создать две доски и добавить на первую компонент на вторую. Компонент отображается на первой. |
| AC-05 | FR-05, NFR-04 | Переименовать целевую доску. Компонент продолжает ссылаться на неё; предпочтительно, чтобы отображаемое название обновилось. |
| AC-06 | FR-06 | Активировать компонент и проверить, что открылась правильная целевая доска. |
| AC-07 | FR-07 | Обновить страницу или повторно открыть приложение. Доски, элементы и связи сохранены. |
| AC-08 | FR-08, NFR-02 | Удалить целевую доску и открыть исходную. Исходная доска доступна, компонент помечен как недоступный, приложение не падает. |
| AC-09 | NFR-01 | Участник, не реализовавший проверяемый экран, выполняет основные операции через интерфейс. |
| AC-10 | NFR-03 | В протоколе зафиксированы браузер и версия; основные тесты выполнены в этой среде. |

# 9. Проверка непротиворечивости

- Каждому сценарию соответствует минимум одно требование.
- Переименование целевой доски не разрывает компонент: связь
  определяется устойчивым идентификатором, а не только названием.
- Удаление целевой доски не удаляет исходную доску и не приводит к
  аварии.
- Требование сохранения данных проверяется после обновления страницы.
- Критерии приёмки описывают наблюдаемые результаты, а не субъективные
  оценки.
