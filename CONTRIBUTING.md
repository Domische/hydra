# Порядок рецензирования и разработки

## Ветвление

| Ветка | Назначение |
|-------|-----------|
| `main` | Стабильная версия |
| `develop` | Интеграция |
| `feature/*` | Новые фичи |
| `fix/*` | Багфиксы |
| `docs/*` | Документация |

## Процесс

1. Ветка от `develop`: `feature/название`
2. Коммиты по Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`
3. Pull Request в `develop`
4. Заполнить PR-шаблон
5. Ревьюер (минимум 1) проверяет
6. Approve → Squash merge → удалить ветку

## Правила

- Не пушить в `main` и `develop` напрямую
- Не мержить свой PR без ревью
- PR до 400 строк
- Один PR — одна задача
